## Portfolio engineering invariants

1. Project identity is resolved through the canonical registry, not filename alone.
2. Prompt is task specification, never the security boundary.
3. Model choice does not grant authorization.
4. Tools are typed capabilities with explicit side effects.
5. Consequential actions require authoritative postcondition verification.
6. Stale turns cannot overwrite newer state.
7. Repository, world and evidence state are versioned.
8. Unknown, hypothesis, evidence, inference and validated fact remain distinct.
9. Multi-model agreement is not proof when assumptions or data sources are correlated.
10. Actual execution identity determines metering.
11. Cloud/edge/local routing may optimize cost and latency but cannot lower mandatory security controls.
12. Influence-oriented systems are defensive by default.
13. Active security testing requires explicit scope, authorization, rate limits and auditability.
14. Generated artifacts require verification before promotion.
15. Strategic claims require concrete resource/competence/capability/action/time mapping.
16. Grand challenges require evidence-backed hypotheses and explicit uncertainty.
17. All-source intelligence requires provenance and counterevidence.
18. Long-context and multimodal inputs are compiled as untrusted evidence unless explicitly authorized otherwise.
19. Explore/exploit decisions are constrained by information gain, cost, risk and reversibility.
20. Simulation and digital twins are advisory evidence, not guarantees about real-world behavior.
21. General model capability is separate from executable authority.
22. Human agency is a measurable system property: choice visibility, reversibility, disclosure and opt-out friction are evaluated.
23. High-sensitivity cognitive/neural data is purpose-bound, consent-gated, minimized and auditable.
24. Legacy project lineage is preserved rather than silently overwritten.
25. No executable task exists without explicit preconditions, capabilities, stopping rules and postconditions.
26. WBS/HTA completeness is validated before autonomous execution.
27. Agent specialization is a capability partition, not an authorization boundary.
28. Crew-style collaboration cannot directly commit privileged state.
29. Deterministic flows govern consequential side effects.
30. AI-generated low-level artifacts remain untrusted until independently verified.
31. Perceived user intent is not authorization.
32. Visual/audio interface state is never authoritative system state.
33. Organizational competence claims require evidence and applicability context.
34. Semantic redefinition is treated as an epistemic risk.
35. Manipulation research is used for detection and resilience, never covert optimization.
36. Reduced monitorability increases required external verification.
37. Simulation is never silently represented as real-world evidence.
38. Targeted network operations require explicit scope and authorization.
39. Human approval is a resumable, auditable state transition.
40. State commits require authoritative readback.
41. Adaptation may optimize behavior inside a bounded safety envelope but cannot redefine that envelope.
42. NPS recommendations cannot override deterministic kernel safety constraints.
43. PUI perception is an input interpretation layer, not an authority layer.
44. Generated UI cannot silently acquire new privileged capabilities.
45. MCP is a capability integration protocol, not an authorization authority.
46. Source-derived performance claims remain hypotheses until independently measured.
47. Duplicate source artifacts are reconciled by lineage rather than destructive replacement.
48. The AETHER/APEX visual prototype is treated as a state-projection reference; its simulated target/decryption behaviors are not promoted to unrestricted operational capabilities.
49. The control fabric separates probabilistic planning/adaptation from deterministic authority, execution and safety enforcement.
