## Portfolio engineering invariants

1. Project identity is resolved through the canonical registry, not filename alone.
2. Prompt is task specification, never the security boundary.
3. Model choice does not grant authorization.
4. Tools are typed capabilities with explicit side effects.
5. Consequential actions require authoritative postcondition verification.
6. Stale turns cannot overwrite newer state.
7. Repository, world and evidence state are versioned.
8. Unknown, hypothesis, evidence, inference and validated fact remain distinct.
9. Multi-model agreement is not proof when assumptions or data sources are correlated.
10. Actual execution identity determines metering.
11. Cloud/edge/local routing may optimize cost and latency but cannot lower mandatory security controls.
12. Influence-oriented systems are defensive by default.
13. Active security testing requires explicit scope, authorization, rate limits and auditability.
14. Generated artifacts require verification before promotion.
15. Strategic claims require concrete resource/competence/capability/action/time mapping.
16. Grand challenges require evidence-backed hypotheses and explicit uncertainty.
17. All-source intelligence requires provenance and counterevidence.
18. Legacy project lineage is preserved rather than silently overwritten.
