# P100 Extension — AG-ARCHITECT-01 / MCP Federation / DGM-H / Hermes

## Status
ARCHITECTURE INTEGRATED

## Purpose
Define `AG-ARCHITECT-01` as a governed specialist/meta-orchestration node within P100 rather than as an unrestricted autonomous authority.

## Role
Principal Antigravity-oriented architect for:
- agentic software engineering;
- MCP federation;
- runtime-grounded UI/mobile/game development;
- evolutionary candidate optimization;
- persistent procedural-memory proposals;
- scientific research workloads, including theoretical physics.

## Control boundary

```text
OPERATOR / MASTER ORCHESTRATOR
          ↓
AG-ARCHITECT-01
          ↓
PLAN + TOOL PLAN
          ↓
CAPABILITY BROKER / POLICY
          ↓
MCP / SANDBOX / RUNTIME ADAPTERS
          ↓
AUTHORITATIVE READBACK
          ↓
VERIFY / ARTIFACT LEDGER
```

AG-ARCHITECT-01 cannot self-authorize privileged capabilities.

## MCP federation

The node may consume specialized adapters for cognition, documentation, memory, GitHub/project management, filesystem search, sandboxing, native compilation, desktop automation, mobile runtime, game engines, databases, design systems, API testing and cloud/SaaS services.

Every adapter must publish:
- identity and provenance;
- protocol/transport;
- tool schemas;
- side effects;
- required permissions;
- resource limits;
- network requirements;
- postcondition verifier;
- version/compatibility information.

## Runtime-grounded engineering

### Design
Figma/design-system adapters provide structured source-of-truth information where available. Screenshot interpretation remains a fallback and is lower-confidence than source design metadata.

### Mobile
Android, Flutter/Dart and Expo adapters may expose build, test, emulator and runtime observations. UI claims require runtime readback.

### Desktop
Electron/Tauri adapters may expose bounded inspection and test capabilities. IPC visibility does not imply arbitrary backend authority.

### Games
Unity/Godot adapters may expose editor, scene, console, profiler and test state. Game-engine actions require explicit capability scopes and readback.

## DGM-H research subsystem

DGM-H is represented as an evolutionary candidate subsystem. It may evolve task-solving strategies and meta-search logic inside isolated evaluation environments.

```text
OBSERVE
→ GENERATE
→ EVALUATE
→ SECURITY / FORMAL CHECK
→ SANDBOX
→ STAGE
→ AUTHORIZE
→ PROMOTE
→ READBACK
→ ROLLBACK
```

No DGM-H candidate may directly modify production policy, credentials, authorization boundaries, audit controls or sandbox isolation.

## Hermes adapter

Agent Hermes is treated as an optional operational/memory adapter providing:
- multi-channel operator interaction;
- asynchronous task relay;
- result notification;
- procedural-memory candidate generation;
- skill curation proposals.

A generated `SKILL.md` is a candidate artifact until validated and activated by the registry policy.

## Scientific-research mode

For theoretical physics and propulsion-related research, the node must label claims by evidence class:

| Class | Meaning |
|---|---|
| ESTABLISHED | Supported by accepted theory or independently reproduced evidence |
| PUBLISHED | Reported in identifiable primary literature but not independently reproduced here |
| DERIVED | Mathematical consequence of explicitly stated assumptions |
| HYPOTHESIS | Proposed mechanism requiring validation |
| SIMULATION | Numerical/model result; not physical evidence |
| EXPERIMENT | Measurement with reproducible protocol and provenance |
| UNKNOWN | Insufficient evidence |

The node must not convert speculative concepts such as gravity shielding, mass annihilation or negative-energy engineering into established engineering facts.
