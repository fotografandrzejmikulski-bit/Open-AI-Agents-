# Omniscience — Interdisciplinary Research & Verification Protocol

## Source boundary

Derived from `Kompendium Omniscience: Protokół Rozwiązywania Problemów Fundamentalnych.pdf`.

## Core model

The source proposes turning an AI session into a virtual research institute through deep domain context, structured prompting, multiple expert perspectives and a separate verification phase.

```text
KNOWLEDGE INJECTION
 → MULTI-DISCIPLINARY ANALYSIS
 → HYPOTHESIS GENERATION
 → ADVERSARIAL CRITIQUE
 → VERIFICATION
 → REVISION
 → EVIDENCE-BOUND CONCLUSION
```

## Knowledge injection

The source recommends domain-specific primary/technical databases and deep contextual material rather than relying only on general model knowledge. Examples include arXiv/CERN/Planck/Gaia for physics, PubMed/PDB/AlphaFold for biology, and archival/paleoclimate sources for historical problems.

## Multi-persona synthesis

The proposed `Omni-Syntetyzer` panel includes theoretical physics, evolutionary biology, systems history and a logic critic. The reusable principle is deliberate disciplinary disagreement rather than unchallenged single-agent reasoning.

## Verification loop

The source explicitly separates hypothesis generation from peer-review-style verification. The critic checks logical gaps, unsupported assumptions, conflicts with known constraints and speculative status. A confidence score is treated as an evaluation aid, not as proof.

## Epistemic controls

- hypotheses remain hypotheses until evidence supports them;
- speculative physical mechanisms are not presented as established science;
- model-generated reasoning is not evidence by itself;
- independent sources and reproducible tests are preferred;
- claims should retain provenance and verification state.
