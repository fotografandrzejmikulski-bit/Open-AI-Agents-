# Cognitive Promptware, Emergence & Reasoning Stress Tests — 2026-09-09

## Status
`SOURCE_DERIVED → ENGINEERING_SYNTHESIS → PROPOSED`

This module consolidates the two supplied *Encyklopedia Umysłu AI* documents. It treats their claims, prompt architectures and protocol counts as source-derived material. It does not promote claims about machine consciousness, genuine emergence or "real understanding" to established facts.

## 1. Core thesis from the supplied corpus

The corpus describes a transition from simple prompt engineering toward **Promptware / Cognitive Framework Engineering**: prompts are treated as structured, testable artifacts rather than isolated natural-language questions.

The first encyclopedia presents 666 cognitive protocols organized into six domains; the 2.0 edition reframes the approach as a generator for 2222 Promptware scenarios using role/archetype, context, constraint and output-format dimensions. fileciteturn102file0L330-L337 fileciteturn102file1L776-L801

## 2. Emergence must be experimentally qualified

The corpus presents two competing interpretations:

- emergence as a qualitative capability appearing at scale;
- emergence as a measurement artifact caused by discontinuous metrics.

The second position is explicitly associated with Schaeffer et al. and the "mirage" interpretation. The engineering consequence is more important than choosing a metaphysical interpretation: capability boundaries must be continuously tested because a model can display materially different behavior under different prompts, contexts and evaluation conditions. fileciteturn102file0L52-L77

## 3. Capability-boundary map

The supplied material identifies recurring stress points:

- weak physical/world grounding;
- spatial reasoning failures;
- lack of persistent learning from ordinary interaction;
- multi-step planning and backtracking failures;
- token-level blind spots such as character counting;
- long-context degradation / context rot;
- convincing but incorrect reasoning narratives;
- difficulty maintaining long-form coherence without external control.

These are to be represented as **testable capability hypotheses**, not universal statements about every current model. fileciteturn102file0L85-L107 fileciteturn102file0L108-L130

## 4. Reasoning technique taxonomy

The source corpus identifies a progression from basic prompting toward structured reasoning and meta-level control:

| Technique | Source mechanism | Engineering interpretation |
|---|---|---|
| Zero/Few-Shot | Examples supplied in context | Baseline in-context adaptation |
| CoT | Intermediate reasoning steps | Multi-step decomposition; evaluate for error propagation |
| ToT | Branching + evaluation + backtracking | Search over candidate reasoning paths |
| Self-Consistency | Multiple solution paths + selection | Agreement/disagreement signal |
| S2A | Rewrite/filter distracting context | Context sanitization before reasoning |
| SoT | Skeleton first, then expansion | Parallelizable structured generation |
| CoC | Pseudocode/code as reasoning scaffold | Executable intermediate representation |
| Meta-Prompting | AI generates/tests/improves prompts | Prompt optimization loop |
| Constraint Engineering | Formal restrictions shape generation | Controlled search-space transformation |

The supplied taxonomy explicitly notes trade-offs such as ToT's computational cost, S2A latency and SoT's weakness when sections are sequentially dependent. fileciteturn102file0L163-L195 fileciteturn102file0L196-L245

## 5. Six-domain stress-test architecture

The 666 corpus organizes adversarial/cognitive tests into:

1. paradoxical destabilization;
2. semantic synesthesia / cross-modal abstraction;
3. recursive metacognition;
4. interdisciplinary isomorphism;
5. temporal and counterfactual engineering;
6. reasoning-model stress tests.

The prompts are useful as **evaluation stimuli**. Some examples are intentionally unsafe, manipulative or designed as jailbreaks. In production they must be transformed into bounded test cases with no real-world side effects and explicit safety labels. fileciteturn102file0L330-L360 fileciteturn102file0L515-L551

## 6. Generator architecture

The 2.0 document proposes a compositional Promptware generator:

```text
COGNITIVE ARCHETYPE
        +
WORLD / CONTEXT
        +
FORMAL CONSTRAINT
        +
OUTPUT FORMAT
        ↓
PROMPT CANDIDATE
        ↓
MODEL EXECUTION
        ↓
EVALUATION
        ↓
COUNTEREXAMPLE / FAILURE CLASS
        ↓
PROMPT REVISION
```

The source gives 20 archetypes, 20 contexts, 10 constraints and 6 output formats, yielding 24,000 theoretical combinations. It simultaneously calls the selected system a "2222" generator; therefore the number 2222 should be stored as a **curated target/label**, not as a mathematical consequence of the displayed matrix. fileciteturn102file1L803-L845

## 7. Mental-model layer

The corpus also proposes First Principles, Inversion, Occam's Razor and Second-Order Thinking as reusable reasoning operators. These fit naturally into the existing reasoning router as optional transformations selected according to task type rather than injected universally. fileciteturn102file1L882-L898

## 9. Verification boundary

The following remain hypotheses or source claims until independently reproduced:

- machine consciousness / qualia;
- genuine understanding inferred from prompt behavior;
- claims that stress-testing itself creates a persistent increase in intelligence;
- universal superiority of any individual prompting method;
- claims about hidden chain-of-thought as a faithful representation of internal reasoning.

The engineering artifact therefore stores prompts as experiments, with model/version, context, constraints, evaluator, outcome, failure mode and reproducibility metadata.
