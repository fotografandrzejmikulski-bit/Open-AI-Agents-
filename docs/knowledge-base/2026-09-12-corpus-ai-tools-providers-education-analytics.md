## Architectural synthesis

The material strengthens the existing capability-registry model:

```text
INTENT
 ↓
CAPABILITY REQUIREMENTS
 ↓
PROVIDER DISCOVERY
 ↓
LIFECYCLE / HEALTH
 ↓
ACCESS / COST
 ↓
AUTHORIZATION
 ↓
POLICY
 ↓
EXECUTION
 ↓
OUTPUT QA
 ↓
PROVENANCE
```

Required state separation:

`CONNECTED ≠ HEALTHY ≠ AVAILABLE ≠ AUTHORIZED ≠ ALLOWED`

A directory entry, logo, ranking or static comparison never grants authority.

## Workflow composition

The corpus supports modeling AI work as typed capability graphs rather than isolated tool selections:

```text
RESEARCH → SYNTHESIS → DESIGN → MEDIA → DISTRIBUTION → ANALYTICS → ITERATION
```

A workflow node should carry capability, modality, quality threshold, privacy class, cost budget, latency target, authorization requirement and provenance requirement.

## Substitution / fallback rule

Paid-vs-free comparisons are candidate discovery only. Substitution requires equivalence checks for:

- semantic capability;
- input/output modality;
- quality threshold;
- context/file limits;
- integrations;
- privacy/data residency;
- licensing;
- latency;
- cost;
- provenance.

Fallback must not silently alter task guarantees.

## Security invariants

- listed tool ≠ available API;
- free ≠ unrestricted;
- paid ≠ trustworthy;
- connected ≠ authorized;
- model name in infographic ≠ current production model;
- citation frequency ≠ source quality;
- generated output ≠ verified result;
- course listing ≠ verified competence.
