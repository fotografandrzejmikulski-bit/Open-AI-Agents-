# Project Genesis — Iteration 10 — OmniDiscovery

## Purpose

This record documents the cross-corpus synthesis that produced Project 79. The objective was not to create another generic AI/research project, but to identify the strongest missing system boundary after reconciling the repository's accumulated knowledge from its earliest agent/MCP material through the latest scientific, mathematical, physical, device, language, game, business and assurance artifacts.

## Synthesis finding

The knowledge base repeatedly converges on the same lifecycle:

```text
QUESTION / INTENT
→ CONTEXT / KNOWLEDGE
→ MULTI-SOLVER REASONING
→ HYPOTHESES
→ CONSTRAINTS
→ SIMULATION / FORMALIZATION / CAUSAL ANALYSIS
→ CONTROLLED EXECUTION
→ AUTHORITATIVE OBSERVATION
→ VERIFICATION
→ REPLICATION
→ KNOWLEDGE UPDATE
```

Existing projects own nearly every component, but no single project owns the **selection of the next most informative experiment** and the persistent evolution of the global knowledge state as a closed-loop controller.

## Existing boundaries that were deliberately preserved

- Project 61 remains probabilistic learning and optimization.
- Project 62 remains data/causal/distributed intelligence.

## Novel system boundary

The new object is the **Discovery Controller**:

```text
COMPETING MODELS
      ↓
WHERE DO THEY DISAGREE?
      ↓
WHICH OBSERVATION WOULD CHANGE BELIEF MOST?
      ↓
WHAT TEST IS FEASIBLE / SAFE / REPRODUCIBLE?
      ↓
RUN
      ↓
READ AUTHORITATIVE RESULT
      ↓
UPDATE BELIEFS
      ↓
REPLICATE
      ↓
PROMOTE / REFUTE / KEEP OPEN
```

This is distinct from ordinary literature retrieval, answer generation, model selection, active learning used only for prediction, or automated lab control without an epistemic ledger.

## Breakthrough boundary

The project must not claim a new scientific law at genesis. Its first breakthrough target is a **validated discovery process** that beats baseline experiment-selection policies on blinded benchmark worlds and then survives real-world prospective replication.

Only after that process is demonstrated should any individual scientific result be considered for promotion.

## Required proof of novelty

Project 79 must demonstrate at least one of:

1. materially better identification of known hidden mechanisms per unit experiment than baseline selection policies;
2. materially lower false-discovery rate at equivalent discovery throughput;
3. higher hypothesis-elimination efficiency at equivalent resource cost;
4. discovery of a previously unknown but independently reproducible result in a bounded real-world domain;
5. a new cross-domain invariant that survives formal or empirical falsification attempts.

No novelty claim is accepted from architecture diagrams alone.

## Safety boundary

The engine can propose high-impact experiments but cannot self-authorize them. High-risk physical, biological, chemical, medical, financial or security operations require explicit domain-specific controls, authorization and human review where applicable.
