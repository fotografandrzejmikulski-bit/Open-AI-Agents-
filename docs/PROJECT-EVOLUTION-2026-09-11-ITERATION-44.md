## Major findings

1. The corpus establishes a repeatable **reference → design spec → skills → implementation → motion → QA** workflow for premium frontend work.
2. 21st.dev is a useful reference/component provider because its current surface exposes prompt-driven React components, templates, themes and animated UI primitives. citeturn0search1turn0search6
3. Webflow provides a large professionally designed template surface suitable for visual reference discovery, but a reference is not equivalent to permission to copy proprietary code/assets. citeturn0search3turn0search15
4. Everything Claude Code reinforces P100's existing separation of agents, skills, hooks, commands, rules and MCP configuration, plus research-first development, verification loops and security controls. citeturn0search0turn0search2turn1search6
5. Kilo Code and OpenCode reinforce provider-neutral agentic development with specialized agents, skills, MCP, model/provider routing and explicit permission mechanisms. citeturn2search0turn2search6turn2search8turn1search13
6. Google Antigravity reinforces the agent-manager/control-center abstraction for orchestrating multiple agents and tasks. citeturn2search16
7. Browser HTML capture should be treated as untrusted external input requiring sanitization, usage-rights review, secret/script detection and independent reimplementation rather than blind cloning.
8. Visual quality requires a first-class visual-regression and responsive-QA boundary; generated HTML that merely renders is not sufficient evidence of production quality.

## Security invariants

- screenshot ≠ source code;
- copied HTML ≠ permission to redistribute;
- component prompt ≠ trusted code;
- installed skill ≠ authority;
- connected provider ≠ authorization;
- generated render ≠ verified render;
- visual similarity ≠ legal equivalence;
- external showcase ≠ local QA evidence.
