# PROJECT EVOLUTION — 2026-09-12 — ITERATION 58

## Input

Eight AI-tool infographics supplied as a new discovery corpus: tool replacement lists, 30-day AI-at-work curriculum, historical tool inventory, generative-AI application landscape, broad software landscape, paid/free comparison, 135+ tool map and marketer-focused stack.

## Audit result

The corpus was analyzed as one batch. No independent product boundary emerged.

The strongest contribution is not another tool collection but a **tool-independent capability and workforce-learning model**.

## Changes to system architecture

### 1. Capability-first routing

Provider discovery now conceptually follows:

`JOB → CAPABILITY → WORKFLOW → CANDIDATES → CONSTRAINTS → POLICY → AUTHORIZATION → EXECUTION → QA → PROVENANCE`

### 2. Human/task boundary

Claims that AI can replace hard work are normalized into task decomposition. The system must identify automatable subtasks, human review boundaries and measured outcomes rather than equating a tool with replacement of a human role.

### 3. Transferable skill graph

The 30-day curriculum is generalized into:

`SKILL GAP → LEARNING RESOURCE → PRACTICE → ARTIFACT → ASSESSMENT → VERIFIED COMPETENCE → SKILL REGISTRY`

Tool-specific knowledge is subordinate to transferable capability.

### 4. Economic routing

Provider selection must account for total cost, including usage/subscription, integration, migration, training, QA, infrastructure, lock-in and operational overhead.

### 5. Fallback verification

Provider substitution must be tested against semantic capability, modality, quality, limits, privacy, integration, latency, cost, licensing, provenance and authorization. No silent substitution when critical constraints change.

### 6. Workflow DAG

Flat tool lists are discovery input only. They should compile into typed work graphs with capability requirements, provider candidates, constraints, evidence requirements and failure semantics.

## Existing-project impact

- **P100:** primary integration — capability/provider registry, workflow DAG, cost-aware routing, human review boundaries, curriculum and fallback contracts.
- **P113:** multimodal provider-adapter layer reinforced by broader image/video/audio/research/application taxonomy.
- **P114:** provenance requirements strengthened for volatile tool/provider facts and generated outputs.
- **P30:** marketing/SEO workflow decomposition and measurement loop reinforced.

## New project decision

`NO_NEW_PROJECT`

Reason: the new material increases the density and generality of existing capability/provider/skill architecture rather than defining a separate runtime, data boundary or product identity.

## Verification boundary

The infographics are not treated as authoritative evidence for current pricing, rankings, product status, feature availability, model versions or claims of labor replacement. They are indexed as discovery evidence requiring independent verification before operational use.
