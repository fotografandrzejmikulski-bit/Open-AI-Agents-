Record how newly acquired knowledge changes existing projects. A project is considered evolved only when the new capability has an explicit destination, contract or verification consequence.

## New cross-project principle

The portfolio now treats **domain adapters** as first-class project surfaces:

```text
GENERIC AGENT / EVIDENCE / ASSURANCE CORE
                 ↓
          DOMAIN ADAPTER
        ↙      ↓       ↘
      GAME   VEHICLE   OSINT
        ↓      ↓       ↓
   DOMAIN STATE / EVIDENCE / UX
                 ↓
          COMMON ASSURANCE
```

This prevents domain-specific projects from rebuilding the same authorization, provenance, replay and verification infrastructure.

## Maximum-evolution rule

For every future source package, the completion condition is now:

1. Extract durable knowledge.
2. Identify every affected existing project.
3. Specify concrete upgrades.
4. Detect capability combinations that justify new projects.
5. Check lineage/duplicates.
6. Create new project artifacts when threshold is met.
7. Update registry and ingestion records.
8. Verify all writes.

An ingestion iteration is **incomplete** if step 2–7 are skipped.
